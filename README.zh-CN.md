# 仓库多机器人调度与导航评测

本项目已实现两个层次。第一层是：C++20 离散模拟器、取货→送货任务、三种任务分配策略、时空 A*、预留表、故障注入、独立碰撞校验和固定种子评测。

它主要补充 C++ 算法、共享资源冲突处理、可靠性和实验设计能力。规划核心单线程，机器人动作按离散时间步同步执行；评测器通过有上限的独立子进程运行实验。不能据此宣称分布式调度服务、真机导航或生产部署。

构建与复现命令见 [英文 README](README.md)。正式评测冻结三张地图、10/30/50 台机器人、10 个种子，共三种方法 270 次，加 lambda=0 消融 90 次；同时记录未完成任务，避免只看成功任务造成偏差。拥堵感知并非所有场景都更好，完整结果和负结果见 [评测报告](docs/evaluation.md)。

已修复并可复现的核心问题是：机器人提前经过目标点时，不能在预留终点到达前完成服务，否则会破坏其他机器人的未来预留。[失败分析](docs/failure-analysis.md)给出了复现命令、修复和故障演示的证据。

第二层是 [ROS 2 Jazzy / Nav2 / Gazebo Harmonic 执行层](docs/sil-design.md)：通过 ROS 服务调用原有 C++ 分配器，运行 1–3 台物理仿真机器人，使用真实的 Nav2 action、AMCL、激光雷达、里程计和独立 TF 命名空间。通道占用在取消或超时后不会自动释放；独立速度闸门在输入过期时停车。

```bash
python3 scripts/sil/qualify.py --out runs/sil/my-qualification
```

需要 Linux Docker 和 Python，使用项目内的新输出目录。脚本构建兼容容器，运行单机器人、三机器人、激光延迟、执行器暂停、控制节点重启、生命周期响应丢失，以及故意撞墙的接触检测对照；保存 MCAP 原始消息并独立复核位置、间距、停止和恢复。[仿真验收报告](docs/sil-validation.md)记录实际结果和复现方法。

这是软件在环（SIL），不能写成真机或硬件在环（HIL）验证。三个 Nav2 栈同时运行，但保守资源锁串行执行完整任务；没有云端生产运行、硬件安全认证或 ML 训练/推理结果。50 台机器人的数字属于离散评测，物理仿真只验证 1–3 台。此次实现使用了编码代理协助。

已修复启动时无限等待生命周期响应的问题：使用明确期限和实际状态核对，避免超时后重复发送状态切换。通过真实 DDS 故障测试，并在 Gazebo 中丢弃真实 map_server 的配置响应验证恢复。[修复与证据](docs/lifecycle-recovery.md)。底层 Fast DDS 发现竞态仍未宣称根除。
